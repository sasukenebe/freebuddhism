# Tree labels and collection-page copy: proposals only

Date: 2026-11-08. Status: FOR REVIEW, NOT APPLIED TO WEBSITE.

## Scope and recommendation

Keep each tree row short: the existing name, then a short English meaning.
On its collection page, keep the same name as the heading and put one descriptive
sentence below it. Keep availability and translation choices separate from that sentence.

These are proposed browsing labels, not a new translation of the underlying works.
The English descriptions follow the existing reference metadata in
[site-catalog.json](../../metadata/site-catalog.json). Some traditional titles have
several reasonable English renderings; the owner should choose the preferred wording.

The list below covers all 41 collection objects currently defined by the shared
navigation. Rules for numbered books, chapters, individual texts and editions follow
it; they cover those repeated objects without inventing thousands of new summaries.
A description does not claim that the collection is completely translated locally.

The website's Home page is different from a collection page. Restore its original
paragraphs and do not replace them with these proposed collection descriptions.

  - Tree labels: AN 1 — Ones; AN 2 — Twos; AN 3 — Threes; AN 4 — Fours;

  - Page sentence: Discourses arranged around sets of one, two, three, four, five,
    six, seven, eight, nine, ten or eleven respectively.
  - If these groups do not have their own page, do not invent a new route just to
    display that sentence.
- All 52 named Aṅguttara chapters:
  - Tree: recorded reference range — recorded English chapter name.
  - Page heading: recorded Pāli name, with the English name directly below.
  - Use the exact names and ranges in
    [anguttara-menu.json](../../metadata/anguttara-menu.json); do not infer a
    chapter name for an individual sutta.
  - Example tree label: AN 1.1–10 — The Chapter on What Occupies the Mind.
- All 22 Vinaya Khandhaka chapters:
  - Tree: chapter number — recorded English chapter name.
  - Page heading: recorded Pāli title, with the English name directly below.
  - Use the exact existing reference entries in
    [vinaya-khandhaka-menu.json](../../metadata/vinaya-khandhaka-menu.json).
- Other recorded books, chapters and rule classes:
  - Tree: reference or existing Pāli name — existing English name, when recorded.
  - Page: the same heading, without a guessed summary.
  - Do not introduce arbitrary blocks of 25 or fabricate missing metadata.
- Every individual text:
  - Tree and page heading: reference — existing text title.
  - Example: MN 1 — Mūlapariyāya Sutta, if that title is recorded for the object.
  - If only AN 1.11 is recorded, display AN 1.11. Do not borrow a parent chapter
    title or generate a supposed translation of a missing title.
  - Put available translations and audio underneath, not inside the title.
- Every translation/edition:
  - Choice label: recorded translator name; add the edition label only if needed
    to distinguish multiple editions by the same translator.
  - Reader heading: the text's reference and title, then the translator.
  - Current edition is plain text, not a link back to itself.
  - Missing local editions remain non-clickable status text.

## Easier expansion: three later local prototypes

All three keep the same font family, ordinary HTML, existing page width and words.
They are proposals, not changes in this release.

1. Full-width disclosure row, recommended.
   Clicking anywhere on the collection summary expands it. Give the row a larger
   click area, visible keyboard focus and a distinct Open collection link.
   The label does not need the word expand.
2. Larger plus/minus control.
   Keep the familiar indented tree, but use a large accessible toggle next to a
   separate collection link. More explicit controls, but more visual clutter.
3. Expandable subsection headings.
   Use ordinary heading-sized disclosure labels and lists beneath them.
   Very plain, but deep trees need care to avoid oversized nested headings.

Compare the three on the same Tipiṭaka/Vinaya/AN content, by mouse, keyboard and
phone. Try taller targets before changing default font size. Let readers use the
new Font Size - / + controls independently of any future expander choice.
